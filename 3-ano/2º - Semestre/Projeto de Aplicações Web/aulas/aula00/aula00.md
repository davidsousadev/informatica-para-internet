# 1. O QUE É UMA APLICAÇÃO WEB?

**Aplicação Web**

Sistema que funciona pela internet e é acessado, geralmente, por meio de um **navegador web**.

Permite:

* acesso a serviços e informações
* comunicação
* comércio eletrônico
* gerenciamento de negócios
* armazenamento de dados remotamente

**Exemplos:**

Site de compras | Banco online | E-mail | Sistema escolar | Redes sociais

---

# 2. O QUE É UM PROJETO?

**Projeto = esforço organizado para resolver um problema**

Características:

* possui **começo e fim**
* utiliza **recursos**
* busca resolver um **problema**
* possui **objetivos**
* precisa de **planejamento**

### Projeto de uma aplicação web

**Necessidade → Objetivo → Requisitos → Planejamento → Desenvolvimento → Implementação → Manutenção**

---

# 3. POR QUE PLANEJAR?

Antes de escrever código:

**1. Identificar necessidades**
**2. Definir objetivos**
**3. Definir requisitos**
**4. Escolher tecnologias**
**5. Planejar recursos**
**6. Estruturar as etapas**

### Sem planejamento:

**Problema → Código sem direção → Retrabalho → Aplicação que não resolve a necessidade**

### Com planejamento:

**Problema → Planejamento → Desenvolvimento → Solução**

---

# 5. COMO O NAVEGADOR ENCONTRA A APLICAÇÃO?

### URL

**URL = Uniform Resource Locator**

É o endereço utilizado para localizar um recurso na internet.

Exemplo:

**https://www.exemplo.com**

---

# 6. HTTP E HTTPS

### HTTP

**Hypertext Transfer Protocol**

Protocolo de Transferência de Hipertexto.

Usado para comunicação entre cliente e servidor.

### HTTPS

**Hypertext Transfer Protocol Secure**

HTTP + **camada de segurança**

Utiliza **TLS/SSL** para criptografar a conexão.

### RESUMO

**HTTP → comunicação**

**HTTPS → comunicação + criptografia**

---

# 7. FRONT-END × BACK-END

## FRONT-END

É a parte da aplicação que é:

* exibida ao usuário
* processada no navegador
* responsável pela interface

**HTML → estrutura**

**CSS → estilo**

**JavaScript → comportamento/programação**

---

## BACK-END

É a parte responsável por:

* processamento de dados
* regras de negócio
* conexão com banco de dados
* processamento no servidor

---

# 8. COMO FRONT-END E BACK-END SE COMUNICAM?

### API

**API = Application Programming Interface**

Interface de Programação de Aplicações.

Permite:

**FRONT-END → API → BACK-END**

e

**BACK-END → API → FRONT-END**

### Fluxo simplificado

**Usuário**

**Front-end**

↓

**Requisição**

↓

**API**

↓

**Back-end**

↓

**Banco de dados**

↓

**Back-end**

↓

**API**

↓

**Front-end**

↓

**Usuário**
